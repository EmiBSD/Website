---
title: N5, the VFS and the file systems, is met
description: The buffer cache, the vnode and mount layer, name lookup, the VFS system calls and eight file systems now live in the safe kernel crate.
---
Milestone N5 closed on 2026-11-07, tagged
[`n5-vfs`]({{ site.repo }}/releases/tag/n5-vfs). In ten slices, from 2026-10-28 to
2026-11-07, the VFS and the file systems left the LandingZone tree for `kernel::fs`, in the
crate the compiler refuses to build with any `unsafe`:

- **The VFS layer:** the buffer cache, the vnode and the mount, with the vnode and mount
  operations as two Rust traits; name lookup, the name cache and getcwd; files and record
  locks; the VFS system calls; raw device I/O, special files and deadfs.
- **Eight file systems:** ffs (the UFS layer it shares included) and mfs, ext2fs, msdosfs,
  cd9660 and udf, tmpfs and fuse.

Two file systems stay in the LandingZone tree for now, adapted to the new traits: nfs moves
with the network stack at N6, and ntfs, built on amd64 only, waits for N10.

The system-call layer is now linked into the kernel image, and 170 of the 331 system calls are
handled natively, from 105 when N5 started. The whole test suite passed on arm64, on two and on
four CPUs, with the installer end to end, and the comparison with a real OpenBSD found no new
difference.

The cost is measured too: under QEMU on arm64, against N4, a cold file read is 6.7 % slower
and fork plus exit 7.9 % faster; the page fault, fork plus exec, pipes, TCP and the boot did not
change. The file read goes to N12, the performance milestone.

Next is N6: the network stack, and nfs over it. The [Status]({{ '/status/' | relative_url }})
page has the details.
